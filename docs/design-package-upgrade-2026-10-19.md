# 设计包消费流程升级

本次围绕“功能已完成→选参考App→AI拉取并应用风格”调整总库。

## 交付变化

- 新增多邻国Design Package v1：441项token/声明、28族组件、18布局、76交互、22动效记录。330张允许的原版/参考画面和4份参考动效录屏随包提供；原生工程、当前参考APK及Paperlane迁移保留。
- 小米升级为标准包：161项token、十组件、三布局、34组导航/弹层规则、51项源动效候选和3项目标D动画方案；完整原件与旧对照保持原字节。
- Kimi升级为标准包：192项token、七类核心组件、四布局、243个来源观察区间和七组目标契约、菜单观察与3项D动画方案。原Run03分发政策与全部原件保持不变。
- 三者增加面向AI的README、DESIGN_SPEC、ADAPTATION_GUIDE与可搜索的组件/动画/截图浏览器。小米不再链接未分发的APK；Kimi命令改为当前目录的distributed模式。
- 新来源必须标准格式并满足消费者契约：核心组件、用户状态逻辑和可实施动画参数不能是空模板。Hark/Mirasim保留明确legacy-research状态。
- README与网页复制任务直接指导AI保留目标业务和技术栈，实际实现视觉/动画/用户逻辑并运行对照。修复首页移动端装饰溢出；参考录屏支持正确MIME和HTTP Range。

## 多邻国分发边界

采用文件白名单投影，没有复制研究主机约19.5GB的工具/AVD缓存。原APK、账户/Feed/身份画面、原始操作日志和签名中间件不入库。源图/资产字节不变；capture metadata明确标注为消费者D投影，保留原metadata SHA。134份私密/诊断/上下文证据仅保留withheld标记、SHA和原因。实际入库文件以catalog/manifests为准，原件仍在研究主机。

## 验证范围

39项Node测试通过，包括拒收旧格式新来源、拒收空组件和无可实施动画的包、隐私路由、视频Range、标准新旧入口。build生成五来源目录，公开输出不带原始证据。verify对31,615个研究文件及三个标准包执行哈希/引用/消费者契约检查。

Kimi原消费者验证通过：257套A、71套D保持原字节，scopeComplete仍false。三份新设计浏览器的组件、动画、搜索、截图、390px布局和视频播放共16项通过。统一目录浏览器检查另记当前实际运行结果于`.runtime/browser-qa.json`。

本次没有控制原App/模拟器或把历史观察改成新运行。partial保留真实差异，同时提供能在目标中实施的D替代；不将原业务全测作为用户应用风格的前提。
