# 给AI的实施约定

用户已完成功能与基础UI，现在要应用选定App的视觉、动画和通用用户逻辑。用户已选来源时直接读取并实施，不重复要求选型，不把任务退化为报告。

1. 用现有Git权限拉取本库，记录实际commit；读取根AGENTS和选定来源标准入口。可稀疏检出来源与skill。
2. 审查目标框架、路由、业务状态与现有组件。建立“来源规则/素材→目标组件→采用或适配→验证”的映射。
3. 实现文字、颜色、留白、形状/表面、图标层级、高频组件及布局。用真实内容检验长文和密度，不只改主页和主题色。
4. 实现初始、选中、禁用、忙碌、空、错误，以及返回、草稿、保存取消、重试和多层弹窗。视觉状态与业务提交分开，避免丢失数据。
5. 实现动画触发、duration/delay、easing、退出、中断/重入与减少动画。来源未知时使用包内D方案，记录为目标选择。
6. 沿用目标业务接口、数据与技术栈，替换来源品牌/文案。参考里的mock成功、假加载、权限说明占位不接入正式产品。
7. 实际运行代表页面/状态，检查窄宽屏、中文/长文本、大字、IME、键盘/focus、系统栏；对照改造前后和来源样本。
8. 交付改动、运行结果、截图/录屏、具体差异与剩余问题。原版研究覆盖、目标实施完成与迁移效果分别报告。

默认不为风格迁移重测原软件全部账号、支付、协议、算法或业务分支。只有影响目标UI的缺口才定点补证。
