# 迁移接入指南

当前库可用于选取设计规则和定位原始资产，并提供独立 Java Android View 参考与 Fieldnotes 迁移样本。运行验收见 [D 结果](../reference/run03-acceptance.json)，来源差异见 [原版配对](../comparison/native-run03.md)，不同业务见 [Fieldnotes](../transfer-example/run03-acceptance.md)。它是研究参考，原版受限路径、物理设备、字体和后端语义仍有缺口；当前任务状态以 [37 项清单](remaining-validation.json) 为准。

本轮补充的输入/导航/异步/保存/风险动作/语言规则集中在 [run03-behavior-and-transfer](../spec/run03-behavior-and-transfer.md)。先读来源事实与条件，再使用 [组件契约](../reference/component-contracts.json) 和 [来源映射](../reference/source-mapping.json)。本地持久化、六秒fixture与epoch取消均是D策略，不能宣传为原版内部实现。

## 保留的候选习惯

- 内容页将注意力留给主内容，在屏幕边缘放较轻的工具入口；设置页通过浅背景、分组表面与分隔线组织信息。依据：真实主页、抽屉、设置原图。
- 高频图标动作有独立圆形命中区；设置导航使用整行入口、右侧摘要或方向提示。语义命中范围与视觉边界分开，见 native-observed tokens。
- 简单选择（本轮主题、语言）直接在当前页更新选择标记与显示结果；字号页另有显式 Save。迁移时按任务性质选择保存模型，不能统一做成自动保存。
- 空态同时解释原因并提供下一步：未登录历史区给出同步说明和登录动作。换到其他业务时替换原因与动作，而非保留“登录后同步会话”措辞。
- 深浅主题要维护语义层次和变体资产；原生主题与 widget 内容主题分别接入，再检查交界处。

这些是研究范围内的候选规则。所有推断都不能扩大成“全 App 永远如此”。

## 接入步骤

1. 读取 `library.json`、覆盖表及原图，确认适用平台/版本/语言/主题。
2. 审查目标项目的导航、输入、异步、保存与权限模型，做“来源规则→本项目组件/状态→保留/适配/替换”的映射。
3. 先接语义色、排版层次与动作布局，再接行为与用户引导；使用目标项目原有业务和品牌。
4. 从 assets/manifest.json 找到原件及来源。Kimi品牌、模型名、第三方SDK文案应保留在研究库，应用到新产品时使用另存的新内容与自有品牌。
5. 参考 `tokens/widget-foundation.json` 时保持其 inline widget scope，不能把CSS px直接当原生dp/sp。每个来源token到新平台token的映射是D选择。
6. 先实现正常/空/错误/忙碌/退出返回，再按已证据的行为契约核对。未知部分选择明确的D策略，写明与来源未验证。
7. 用同环境原版对照检验相似点与偏差；另选不同业务样本验证可迁移性。两个验证结果分开报告。

## 不应直接搬走的内容

Kimi 的品牌资源、模型入口、聊天生成特定规则、登录/账号协议与第三方验证码模板不是通用设计规则。包内仅“存在”的字体、图标或能力也不能直接认作当前使用。研究原件留存与公开分发是两件事，本轮未发布。

字体替换后需重新比较中西文、数字、长文本和行高；六个Compose字体的文件名、OS/2字重与实际字形覆盖已有独立记录。中文逐字回退未知，不能把拉丁字体文件当作完整中文字体栈。
