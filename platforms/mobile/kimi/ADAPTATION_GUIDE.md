# 在已有产品中应用Kimi

先读取design-package.json、DESIGN_SPEC.md及所需模块，再检查目标项目的技术栈、路由、组件和数据状态。用户已指定本包时直接实施，不重复让用户选择风格。

1. 建立“来源规则 → 目标组件/页面 → 保留/替换 → 验证状态”的小表。
2. 先调整文字角色、留白、形状/表面，再改高频组件与布局。使用目标已有组件体系，不为复刻风格整体换栈。
3. 把animations和interactions中的状态落实到真实产品：初始/选择/禁用/加载/错误、保存取消、返回、草稿与重试；保留目标业务的数据和接口。
4. 动效有来源参数则按条件复用；未知则使用目录中的D方案，记录其为目标选择。处理重入、中断、减少动画及卸载清理。
5. 运行真实页面和交互，检查窄宽屏、长文本、大字、键盘、focus、系统栏。核对功能没有被样例fixture或边界占位替代。
6. 输出改动文件、实际运行结果、前后对照和剩余差异；不要只交一份计划、调色板或静态主页。
