# Hark Web 元素用于手机：可实施路线

用户于 2026-10-22 明确要求继续逆向 Android；若正常运行仍受限，可用已有 Hark Web 元素适配手机。这里采用本库已经保存的 Web 研究，不把 Web 的原版观察改写成 Android 运行结果。

## 可直接体验和复用

启动 `node reference/serve.mjs` 后打开 `/web-mobile.html`；原生静态规范参考仍是 `/index.html`。右上设置内可切换主题、模拟一次失败、返回另一份参考。桌面还显示来源切换说明。

复用入口：`reference/web-mobile.css` 的独立 `--web-*` token、`web-mobile.html` 的布局插槽、`web-mobile.mjs` 的目标交互包装，以及既有 `model.mjs`。没有载入原厂脚本、字体、帐号或服务；数据是本地合成示例。三段导航、记录检索、模板填入、详情、完成/撤销、发送、失败重试和取消都有实际行为。

safe area 使用浏览器 inset；VisualViewport 变化调整可视高度。键盘差值 100px 的判定、48px 容器边框补偿、44px 级触控控件、底部面板 220ms 曲线和请求等待 1300ms 都是目标 D 选择。真机 IME、系统返回、原生动态字体和触摸硬件仍需目标 App 验收。参考设置采用底部面板，不能据此推断 Hark Android 也采用这种外形。

## 接到 Vivic 的落点

| 来源设计关系 | Vivic 对应位置 | 需要保留的行为 |
| --- | --- | --- |
| 轻导航 + 独立内容滚动 | 手机连接概览、控制、卡片列表 | 连接、撤销、断线恢复均接已有 client，不能只有可点的外观 |
| 浮动玻璃输入 + 明确发送状态 | `MobileConsole` 的指令输入 | 中继接收、电脑执行、成功、未知结果必须继续区分 |
| 主次卡片动作 + 详情层 | 画布切换、固定、后续聚焦/迁移入口 | 已授权的真实能力才显示，维持 owner/版本/保存确认 |
| 动态内容容器 | 既有声明式卡片 renderer | 取其视觉层级，继续使用已校验 Card 协议；包内 `bodyTSX` 是 Hark 的另一套实现机制 |
| 返回、取消、草稿、反馈 | 已有请求状态机与客户端内存状态 | 取消不伪称撤回已提交动作；不把参考的合成成功改作真实执行回执 |

当前交付是研究与可运行迁移参考，未重写已部署的 Vivic 手机页面。它证明 Web 元素能在手机尺寸下组合与交互，不证明原生 Hark 界面已经运行，也不证明 Vivic 原生 APK 已完成。

## 验证

实际浏览器结果见 [记录](comparison/web-mobile-verification.json) 与 [对照说明](comparison/README.md)。7 个场景覆盖 390px 尺寸、320px、横屏、主题、减少动画、导航/草稿保留、模板、发送/检索、失败重试、取消和返回。没有外部请求或页面错误。A/B 仍来自旧 Web 研究；本轮重新阅读与独立参考测试全部作为目标 D 记录。
