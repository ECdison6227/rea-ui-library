# 下次可直接交给 Agent 的任务

将下面提示词连同这个研究仓库和你的软件源码一起给Agent。填写两个路径与平台即可；不需要本次聊天记录。

```text
请把我自己的软件改造成与参考App有一致产品家族感的产品，迁移视觉语言、交互策略、用户引导及可复用的软件行为。

研究库：<本仓库路径>/analysis/ui
我的项目：<目标软件源码路径>
目标平台与本次范围：<Android/iOS/Web/桌面；先改哪些模块>

先读取研究库 README.md、baseline/spec.md、baseline/contracts.json、baseline/behaviors.md、baseline/popup-navigation.md、baseline/popup-navigation.json、baseline/coverage.json、baseline/comparison/final/index.html 和 migration-guide.md。运行库中的原生参考，查看三页原图对照与跨业务页。覆盖表为准：A运行事实、B代码、C推断、D独立适配不能混写；历史A不能当本次重新实测。

然后审查我的源码，找到实际框架、路由、主题、字体、基础组件、数据/权限/账号状态和现有测试。优先接入现有栈，保持我的业务、品牌、用户数据与已有正确性。

建立一张可审查的映射表：「来源规则 → 我的项目位置 → 保留/替换/平台适配 → A/B/C/D依据 → 验证方式」。不仅换配色，还要覆盖标题角色、中文/数字字体、留白和信息密度、表面与圆角、导航/返回/重选、滚动保留、前置条件guard、加载/空态/错误、权限时机、恢复与引导。

必须逐弹窗、逐入口路由建立行为矩阵。每个弹窗分别写：何时出现、取消按钮、系统Back、遮罩点击、叠加/替换/排队、重复触发、跨页、后台恢复、退出/卸载/延时结果的生命周期；每条路由分别写来源页与入口、目标、push/replace/tab/overlay、Back去向、栈层、scroll/selection/input的保留或重置、系统主题重建后的状态。每个字段标A/B/C/D或unknown。一个确认可点外关闭不能推成全部弹窗统一策略；队列代码不能当运行压力测试，参考页面缓存不能证明来源全部返回保留。

先迁移tokens和十基础组件，再接代表页面。复用可运行参考的组件结构与接口，业务文本、图标、数据、后端和路由换成我的。三环、健康阈值、穿戴设备、医疗服务、小米账号及运营会员不默认移植。原版未知行为由目标需求作出明确D选择，不伪称来源事实。

实现并运行，不停在建议或静态报告。在同一设备/窗口、主题、语言、fontScale与内容状态下保留目标改造前后截图；需要检查来源时使用研究库对应版本原图。检查实际导航/返回、状态保留、取消、重复触发和失败恢复，列出实际差异。测试自己做的mock状态不能证明原版同样表现。

如果库中证据已足够，不重复安装或全包逆向。只有来源缺口影响当前实现时，使用 rea-style-library，并按其委托调用 reverse-engineer-anything/REA，补特定页面、状态或源码链。先核对目标版本/哈希和生效RN包，运行实物，保存来源A与准确B；不能拿独立重建截图当原App。

交付改好的可运行项目、映射表、验证图/记录、残留偏差与unknown。完成度按实际功能与对照判断，不按报告长度、文件数、解析数或自行发明的相似度百分比。不要自行公开发布仓库。
```

如果是研究一个新参考App，用以下简版：

```text
请用 rea-style-library + REA 从 <App/安装包/URL> 建立可离开聊天独立使用的产品风格库。目标是让我以后结合任意自有软件源码，迁移其视觉语言、交互习惯、用户引导和通用软件行为；不默认克隆其业务。

请先建立三个代表页面、十基础组件的真实运行证据、可实施规格、合适平台的可运行参考与原版对照，再用一个不同业务页面证明复用。记录版本/生效包、主题/密度/字体/状态；逐条区分A观察、B代码、C推断、D实现；通用行为与业务专属规则分开。覆盖表写verified/partial/unverified并留下unknown，所有关键规则可追到原图/源码/实现/对照。完成运行和对照，不停在静态报告。

请另交逐弹窗/逐路由矩阵：出现条件、取消/Back/遮罩、叠加或排队、重复触发、跨页与退出生命周期；来源入口/目标/栈层、返回后scroll/selection/input保留重置和主题重建逐字段记录，unknown不补造，不泛化统一策略。
```

“调用REA”本身只说明工具，不会自动规定交付目标。上述提示词明确了任务的输入、保留边界、实现步骤和验收证据；研究库的覆盖表与实际源码才是下一位Agent应遵循的上下文。
