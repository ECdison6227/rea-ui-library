本指南是历史通用附录。当前可运行三页/十组件以 [baseline/spec.md](baseline/spec.md)、[contracts.json](baseline/contracts.json)、[popup-navigation.json](baseline/popup-navigation.json)、[Java实际API](android-reference/java-api.md) 与最终覆盖表为准。下面的旧静态条目不能覆盖当前实测。

本指南用于把设计语言迁移到其他业务，依据与例外见 [原生规范](design-system.md)、[RN规范](rn-pages.md)。业务功能不需要与健康、运动或穿戴一致。

**先选基线，再换业务**

原包包含 Android原生、RN和旧兼容页面，先按页面选基线。`#FAFAFA`是部分原生容器声明，不能覆盖当前设置白页与健康页的局部白色/渐变；RN我的页为`#F6F7F9`，卡片深色为`#191919`。当前运动/我的正文是RN，不能用同名旧XML替代。具体取值以当前规格和匹配状态原图为准。

对新项目可以在一套渲染技术中实现这些规则，但必须保留角色、密度和状态关系。内部代码架构可以重新组织；不能把反编译类名当成新项目的组件边界。

| 要保留的设计语法 | 新业务如何替换 | 常见偏差 |
| --- | --- | --- |
| 固定主导航 → 页头大标题/轻子标签 → 分组卡片 → 详情 | 主导航换成新业务的稳定领域入口 | 把每个二级功能都塞进底部导航 |
| 大标题轻字重，数据值突出，单位/说明退后 | 指标可换成项目数、预算、任务或库存 | 每行标题都加粗、所有数字都放大 |
| 低对比页面底色承托内容卡，品牌色用于主要操作和选择 | 保留动作色/层级，图表按新数据语义配置 | 橙色覆盖所有图标、边框和成功状态 |
| 主内容滚动所有者明确，页头/主导航各自固定 | 保留主要纵向滚动；卡片内部按需要展开 | 多层可滚动区域抢手势 |
| 值/单位基线对齐，卡片有有值/无值、异常、可钻取条件 | 把“健康异常”替换成新领域的真实警示 | 为了好看给所有卡片塞箭头和异常文案 |
| 通用行的视觉禁用与解释动作分开 | 前置条件不足时解释或引导，限制操作本身仍禁止 | 灰色行完全失去反馈，或仍执行危险动作 |
| 过渡期间限制重复触发，设置行有具体节流策略 | 绑定到对应组件，不给整个 App 人为加延迟 | 所有点击统一等待 300ms |
| 自动刷新与显式刷新分开，前置资源准备有进度和恢复 | 刷新新业务数据、准备导出模板或附件 | 把导航当成网络成功后才立即出现的黑箱 |
| 详细页带入源对象/日期等上下文 | 使用 itemId/date/sourcePage 等业务上下文 | 返回后丢失用户原先看的对象和位置 |

**一个具体迁移示例**

假设新业务是项目管理，原型已经有项目、任务、成员和偏好设置：

1. 把主壳组织成概览 / 计划 / 资源 / 我的，延用图标在上、标签在下的导航密度。四项是本示例的实施选择，原 App 的四个名称不应复制到新业务。
2. 概览保留“大标题 → 核心指标 → 两列内容卡 → 次级内容”的阅读顺序。三指标可替换为进行中、待处理、已完成；它们的业务定义独立于 UI。
3. 卡片进入项目/任务详情时带入原对象和日期；无数据时给明确说明与创建入口，加载/错误/权限不足分别建状态，不能只用 0 表示所有失败。
4. 设置保留分组、图标/标题/说明/尾部控件的角色及明暗层级，字段换成账号、外观、提醒、数据管理。不要把健康设备开关复制成无意义设置。
5. 点击需准备模板的导出操作，进入准备进度，完成继续目标流程，失败允许重试并给简短反馈；保持这个过程模型，替换具体资源与服务。

这类结构化迁移比复制一张截图更能保持整套软件的一致性。研究台中的跨业务页面是此类**重建示例**，不能当成原 APK 页面或实机测量结果。

**字体与单位的实现决策**

- 原包有 mipro 系列系统字体名称、MiSansLatin 的若干字体文件以及专门数字字体。字体文件覆盖不足时不能伪称“完整 MiSans 中文”；以字体清单和目标系统实际回退为准。
- 原生 dp/sp、RN 逻辑尺寸、NativeBase token 和截图物理 px 分开处理。把 dp 转 CSS px 的 1:1 映射只是 `density-independent` 的实现约定；文字还要考虑 Android fontScale。
- NativeBase 存在 `w:9 → 36` 但缺键尺寸原值回退、显式 px 跳过 token 的规则。禁止对所有数字统一乘 4。
- RN 设置行有 `bold:true` 覆盖 fontWeight 的情况。以最终属性优先级决定字重，不能只读一个 fontWeight 字面量。
- MIUI 平滑/自适应圆角不是任意一个 CSS border-radius。跨平台版本可先做明确标记的几何近似，再针对实际基线做视觉校准。

**分开保留三个层面**

`design-tokens.json / tokens.css`保留资源语义；当前契约优先读`baseline/contracts.json`和`android-reference/java-api.md`。`components.json`、旧TypeScript接口和网页模板是历史提炼，不是本轮完整Java API，也不是原作者源码。

新业务可以替换数据库、接口、认证或框架。页面恢复、保存取消、重复点击、权限时机和错误恢复需要逐条适配。医疗/性别/设备能力筛选和48小时设备提醒是原业务规则，不默认迁移；只有目标需求明确需要时才设计对应策略，并标为D选择。
