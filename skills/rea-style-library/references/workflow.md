# 范围、阶段和可复用记录

只读取当前模式需要的段落。以下是跨项目约定，不把某次产品故障、场景编号或设备端口变成永久要求。

## 范围与三条状态轴

默认研究目标是能迁移的视觉语言和核心交互，选择与目标相关的导航、编辑、浮层、反馈、引导与异常样本。研究维度是选题菜单，不是必须全部通过的功能清单。用户明确要求全功能或指定清单时遵从，不自行改成抽样。

用三个独立字段回答不同问题：

| 字段 | 回答 | 不可由什么推导 |
|---|---|---|
| research coverage | 原版哪个条件、规则或功能实际证实到何种程度 | 文件数、参考测试、用户愿意交付 |
| migration readiness | 哪些规则/组件已有可用规范、实现和对照，使用时有什么限制 | 原业务是否全部可用，或单张截图相似 |
| agreed delivery | 用户此次约定的结果是否交付并满足验收条件 | 全部研究维度自动转成任务，或沉默等同接受 |

例：原版支付和双设备同步仍unverified，不妨碍有证据的菜单/输入器规则可迁移。若用户要求的是完整同步验证，缺第二设备仍使该项未完成。用户明确接受延后同步、先完成UI迁移时，记录调整后的验收范围与用户指令位置，原研究覆盖仍unverified。不要把依赖的deferred执行状态写成verified；也不要把已决定延后的项目每轮重新变成必要项。

## 阶段闸门

下表的原版采集、D参考与运行验收适用于约定包含新研究或实施/迁移的任务。catalog、纯资料整理、仅评估只核对已有身份、索引引用与消费者依赖，交付相应索引/评估；不新增目标GUI运行、D制作或跨业务运行，除非用户另要求。缺少既有运行证据仍保留其边界。

| 阶段 | 应得到的可审查结果 | 何时进入下一阶段或停止 |
|---|---|---|
| 身份与范围 | 来源/平台/版本、历史可复用项、验收条件、控制者和必要依赖 | 身份可确认且有下一项可执行；缺少会改变范围的信息才请求协助 |
| 原版代表样本 | 有效原图、操作前后状态、局部A/B规则和关键未知 | 证据足够支撑一个小切片时开始参考，不等所有功能调查结束 |
| 可运行切片 | 一个代表流程及其输入/返回/忙碌或失败状态，与原版配对 | 先修会影响后续页面的系统栏、安全区、IME、焦点与尺寸问题，再扩展 |
| 规则与迁移 | tokens/组件/事件/引导及所需资产；按任务补不同业务样本 | 约定模式可追到证据、实现和对照；不因为还可发现功能而无限扩张 |
| 交付与恢复 | 单一入口、可运行方法、已知边界、恢复和依赖记录 | 必要验收已满足则完成；其余仅在用户接受调整范围后排除。必要项受阻则交付部分成果与具体协助请求 |

有清单时沿用清单ID和状态；发现新功能先判断其是否会改变既有规则或约定验收。只将必要补证加入当前阶段，其余记候选范围。不要在每次续接时重开已完成解析或未经要求的全测。

## 依赖与有界复试

先区分身份/工具连接、运行平台、正常认证、服务容量、真实外设、采集方法。设置与风险和已有证据相称的小复试预算；记录预期、实际结果、失败类别和退出条件。没有新条件或诊断理由时，不继续同类账号/服务失败请求。用户明确给定的预算优先。

每项依赖记录 `state: needed|requested|available|deferred`、已尝试方法、具体所需协助、继续条件和最后一次请求。请求账号/设备时说明需要用户完成的正常步骤，不把凭据写入日志。用户已明确延后后只在条件改变、用户恢复该项或发现有用的新路线时再提，不每轮催问同一问题。

依赖阻塞时继续独立可测的资产/规则/参考/离线整理。全部剩余必要项都依赖外部条件时，保存可审查部分结果及恢复入口，停止主动重复操作。无法正常运行不是A；模拟数据明确区分“原版前端+fixture数据”与D参考，二者都不证明真实后端业务。

## 多来源入库

先核实入库资格：有可追溯的REA研究入口/实际输出、来源身份和证据边界。项目有UI、属于同一作者、能运行或有“还原”字样，都不证明做过REA研究；普通实现/视觉实验不自动入REA研究库。用户另要实现示例时单独标记并遵从其范围，不给它补造研究结论。已有transfer-example作为来源研究的一部分保留，不默认拆成另一份原版研究。没有匹配REA研究的类别可以留空，不用普通工程充数。

按原版实际产品交付平台分类：网页、桌面应用、手机应用。记录另一个维度的运行栈，如web-browser、Electron、Qt、Android native、WebView；在桌面浏览器看网站不变成桌面原生。在手机浏览器看同一网站可加移动视图标签，不能无证据改成手机原生产品。

每个profile保留原仓库URL、固定Git提交、分支/本地修改说明、源码/研究根目录、证据身份、技术栈、依赖/构建要求、启动目录/命令、预览链接及实际验证日期。Git提交只证明取得的代码身份，不证明客户端运行成功。找不到原平台或提交时标unknown，不从仓库名、截图画布或参考实现猜测。

统一库提供分类、搜索和相对路径入口，引用各独立profile与运行工程。可以通过Git submodule或受控复制固定来源；采用哪种方式服从项目结构。保留各来源风格和原启动方式，不为统一入口把所有工程重写成同一技术栈，也不混合tokens。旧schema以适配映射接入，不覆盖原始研究记录。界面预览属于派生产物，不是来源的新A证据。

## 复用run与捕获结构

优先扩展现有可靠工具。将目标身份、profile/run ID、输出目录、环境、允许操作与分发选择放配置，驱动只保留平台差异；不要复制多个只改产品名/端口的脚本。可采用[manifest模板](../assets/research-manifest.json)，也可把旧格式映射到相同信息，无需迁移全部原件。

模板使用以下集合；空数组表示尚无记录，不表示通过：

| 集合 | 最小信息 |
|---|---|
| profile | 独立来源ID、可追溯研究身份、原平台/运行栈、Git/制品/URL身份、启动方式 |
| scope / delivery | 模式和验收条件；各条件pending/met/accepted_with_boundary；明确接受边界的用户指令位置和时间 |
| readiness / coverage | 可迁移部分及限制；来源或D对象、runtime/static、verified/partial/unverified/not_applicable及依据 |
| targets / runs | 原版或参考身份、控制者、起止、origin/current或historical、环境、账号/fixture模式；不保存凭据 |
| artifacts | 唯一ID、相对路径、真实SHA-256/字节数、A/B/C/D、公开与留存边界 |
| captures | 唯一ID、run/target、方法、起止、atomic、各通道时间和artifact引用、像素/控件复核及限制 |
| distribution | default=deny，逐项审核通过的artifact及固定hash/字节数、审核时间 |

填充字段的可执行合成示例和正反例在[检查器测试](../scripts/check-manifest.test.mjs)。其中数据只用于离线契约测试，不是实际A证据。`capture.parts`使用kind/artifactId/startedAt/completedAt；`coverage`使用subject（source/reference/transfer）、kind（runtime/static）、researchStatus和evidence。原版static的verified需要B原件及anchor，原版runtime的verified需要已复核A capture；脚本无法替代该复核。catalog模式还要求profile.researchIdentity显式documented并引用来源研究证据；这只检查声明可追溯，不自动证明REA资格真实。

截图与UIA/DOM是分次采集时记录 `atomic: false`，各part分别有startedAt/completedAt。记录的顺序须真实，状态不一致则保留限制或重采新ID；不覆盖旧原图。若供应方确实提供原子采集才用true并引用其保证。成功写文件不等于review accepted；复核需实际查看图和相关控件。

每次运行新run ID，原件不可覆盖；同一设备/窗口/页面只有一个主动控制者，动作前核对身份。锁只能约束采用该锁的工具，不能替代控制者协调。原版、参考与迁移工程分别建target；D不借用原版包名、账号或capture ID。

可运行无依赖的离线检查：

```sh
node /path/to/skill/scripts/check-manifest.mjs /path/to/library/research-manifest.json
node /path/to/skill/scripts/check-manifest.mjs /path/to/unpacked/research-manifest.json --distributed
```

默认要求全部已声明原件；distributed仅读取精确允许分发的文件，遗漏原件仍作为metadata追踪，不称已交付公开证据。脚本不改文件或状态，不连接GUI、Git或网络，不重新看像素，不验证账号权限，也不证明来源行为或用户授权。它不审核实际ZIP成员；生成归档时另核对实际成员路径和字节。

## 分发与续接

留存原件和公开交付分别记录。对身份页、私人内容、不完整/未审核capture、受限资产使用默认拒绝的分发名单；不把所有withheld都称为隐私。名单固定实际路径与hash，派生预览也按同样边界。分享前在不包含根原包、本机profile及排除原件的隔离目录验证相对路径和依赖；完整本机目录通过检查不足以证明交付可用。

续接入口给出约定目标、三条状态轴、最后已完成阶段、正在等待的依赖、唯一控制者、最新run、来源版本、启动/验证命令和下一项必要工作。恢复本轮配置并实际核验；未知初始状态、登录有效期、先前未读取的剪贴板等只报告已知范围，不宣称精确恢复不可知值。
